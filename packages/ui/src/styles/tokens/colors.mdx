# Colors

The palette is defined as Tailwind v4 CSS variables in `./colors.css`. Every variable is declared as `--color-*`, so Tailwind automatically generates utilities (`bg-background`, `text-foreground`, `bg-amber`, …).

The palette comes in two layers:

- **Tokens** (prefer these) - semantic names that encode intent: `background`, `background-alt`, `background-elevated`, `foreground`, `foreground-muted`, `foreground-subtle`, `button`, `button-hover`, `success`, `invalid`, `border`.
- **Base colors** - the raw hues tokens resolve to: neutrals (`midnight`, `slate`, `stone`, `ash`, `warm-gray`, `snow`, `white`) and brand (`amber`, `deep-amber`, `sage`, `brick`).

## Usage

```tsx
// Semantic tokens (preferred)
<div className="bg-background text-foreground border-border" />
<button className="bg-button hover:bg-button-hover text-white" />

// Raw CSS variable
<div style={{ background: 'var(--color-background-alt)' }} />
```

**Always start with a token.** Drop down to a base color (`amber`, `midnight`, `ash`, …) only when no token fits and you genuinely need that specific hue - if you find yourself reaching for a base color often, that's a signal a new token should be added instead.

export const Swatch = ({ color }) => (
  <div
    style={{
      width: SWATCH_SIZE,
      height: SWATCH_SIZE,
      background: color,
      borderRadius: 'var(--radius-md, 8px)',
      border: '1px solid rgba(0,0,0,0.08)',
      flexShrink: 0,
    }}
  />
);

export const ColorRow = ({ swatch, name, utility, cssVar, value, resolvesTo, subtitle }) => (
  <>
    <Swatch color={swatch} />
    <div>
      <div style={{ fontWeight: 600, fontSize: 14 }}>{name}</div>
      {subtitle && <div style={{ opacity: 0.65, fontSize: 12, marginTop: 2 }}>{subtitle}</div>}

    <div style={{ fontFamily: 'var(--font-mono)', fontSize: 12, opacity: 0.8 }}>

## Adding a new color

1. Add the variable under the `@theme static` block in `./colors.css`:

   ```css
   @theme static {
     --color-my-color: #abcdef;
   }
   ```

   Once declared, Tailwind v4 automatically generates utilities (`bg-my-color`, `text-my-color`, …).

2. If the token is **semantic** (its role may outlive its hue), alias it to an existing raw color instead of picking a new hex:

   ```css
   --color-danger: var(--color-brick);
   ```

   This keeps the palette tight - changing `brick` later updates every semantic token that points at it.

3. Register the new token in the relevant `<PaletteGrid>` group above so it shows up in this page. Keep the `value` and `resolvesTo` fields in sync with `./colors.css`.
