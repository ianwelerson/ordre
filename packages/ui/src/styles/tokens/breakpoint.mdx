# Breakpoints

Breakpoint tokens are defined as Tailwind v4 CSS variables in `./breakpoint.css`. Every variable is declared as `--breakpoint-*`, so Tailwind generates a responsive variant for each one (`nav:flex`, `md:hidden`, …) plus the `max-*` counterparts (`max-nav:hidden`).

Unlike the other token groups, this namespace is **not** reset with `--breakpoint-*: initial`. Tailwind's default `sm`/`md`/`lg`/`xl`/`2xl` stay available, and ours are added alongside them. A custom breakpoint sorts into the scale by value, not by declaration order.

## Usage

```tsx
// Mobile-first: applies at the breakpoint and up
<nav className="hidden nav:flex" />

// max-* applies below the breakpoint
<button className="max-nav:hidden" />

// Raw media query
@media (width >= theme(--breakpoint-nav)) { … }
```

> **Don't redefine Tailwind's defaults.** Overriding `--breakpoint-md` would move every existing `md:` in the repo. When a component needs to collapse at its own width, give that width its own name instead.

## Tailwind defaults

Still available, since this namespace is not reset. Reach for these first - only add a custom breakpoint when a component genuinely breaks at a width none of them describe.

Ordre's own breakpoint is marked and shown in sorted position so you can see where it lands: `nav` sits between `md` and `lg`. Tailwind declares its defaults in `rem` (`40rem`, `48rem`, …); the pixel equivalents are shown here at the default 16px root size.

## Adding a new breakpoint

1. Add the variable under the `@theme static` block in `./breakpoint.css`:

   ```css
   @theme static {
     --breakpoint-board: 1100px;
   }
   ```

   Tailwind generates `board:*` and `max-board:*` automatically.

2. Add an entry to both tables above so it shows up in this page.
