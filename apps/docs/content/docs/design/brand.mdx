## 1. Brand Positioning

### What Ordre Is

Ordre is a client communication platform for service providers. It gives every job a private, shareable status board that clients can follow in real time - no app download, no account creation, just a link.

### Who It's For

**Providers** - independent professionals and small service businesses: watch and jewellery repair shops, home renovation contractors, auto mechanics, bike shops, freelance developers and designers, appliance repair technicians, and anyone who takes on jobs for clients and needs to communicate progress.

**Clients** - anyone who has left something with a service provider and wants to know what's happening without having to call or text.

### Brand Personality

Ordre sits at the intersection of **precision engineering** and **tactile workshop warmth**. It is not enterprise project management. It is not a generic CRM. It is a _trust layer_ between service professionals and their clients.

The brand communicates three things instantly:

- **Professionalism** - the provider looks good using this
- **Simplicity** - zero friction for the client
- **Warmth** - this is about human relationships, not dashboards

### Creative North Star: "The Digital Atelier"

The experience should feel like a custom-built workbench: every tool has a dedicated place, the materials are premium and durable, and the atmosphere is quiet and focused. We move away from "software as a service" and toward **"software as a craft."**

We achieve this through editorial layout, intentional white space, high-contrast typography, and restrained use of decorative elements.

### Reference Products

These products inform Ordre's visual and strategic direction:

- **Linear** - precision UI, every element pulls weight, nothing decorative exists without function
- **Tally.so** - simplicity as a feature; generous whitespace, single-column clarity, no visual noise
- **Notion** - flexibility sold through visual modularity; modular card grids, neutral palette with purposeful color moments
- **Vivaldi** - bold personality; layout as brand expression, not just container

## 2. Color System

### Philosophy

The palette is rooted in earth tones (Amber, Sage, Ash) and polished by Midnight. We do not use "blue" to signify technology; we use precision, layout, and warm neutrals. Ordre's trust signal comes from craftsmanship, not the default SaaS blue.

### Core Palette

| Role           | Name       | Hex       | Usage                                               |
| -------------- | ---------- | --------- | --------------------------------------------------- |
| Primary Text   | Midnight   | `#1A1D26` | Headlines, primary text, high-authority UI elements |
| Secondary Text | Slate      | `#3A3F4B` | Body text, descriptions, secondary labels           |
| Accent         | Amber      | `#E0913E` | Primary CTAs, active states, highlights, links      |
| Accent Hover   | Deep Amber | `#C67A2E` | Hover/pressed states on accent elements             |
| Success        | Sage       | `#5B9A6F` | Completed states, confirmations, positive feedback  |
| Surface        | Snow       | `#FAFAF8` | Primary page backgrounds                            |
| Surface Alt    | Warm Gray  | `#F0EEEB` | Section alternation, sidebars, input fields         |
| Border         | Ash        | `#D9D6D0` | Subtle dividers, card borders, input borders        |
| Muted          | Stone      | `#8A8680` | Captions, timestamps, helper text, placeholders     |
| Elevated       | White      | `#FFFFFF` | Cards, modals, elevated surfaces, overlays          |
| Error          | Brick      | `#C44B3F` | Error states, destructive actions, urgent badges    |

### Surface Hierarchy

Three tiers only. Complexity in surface layering creates visual noise, not depth.

| Layer     | Token         | Hex       | When to use                              |
| --------- | ------------- | --------- | ---------------------------------------- |
| Page      | `surface`     | `#FAFAF8` | The base page background                 |
| Container | `surface-alt` | `#F0EEEB` | Sidebars, grouped sections, input fields |
| Elevated  | `surface-top` | `#FFFFFF` | Cards, modals, popovers on any bg        |

### Accent Rules

- **Amber** (`#E0913E`) - The spark in the workshop. Used for primary CTAs, active navigation states, links, and interactive highlights. Use sparingly - if everything is amber, nothing is.
- **Midnight** (`#1A1D26`) - Our ink. Primary text, headings, and high-authority UI elements like dark section backgrounds.
- **Sage** (`#5B9A6F`) - Completed/success states only. Not for decoration.
- **Brick** (`#C44B3F`) - Errors and destructive actions only. Not for warnings (use Amber for warnings).

### Border Usage

Borders are a legitimate UI tool. The rule is restraint, not prohibition.

- **Cards and containers:** Use `Ash` at 1px when the card sits on a same-tone background and tonal contrast alone is insufficient.
- **Inputs:** Use `Ash` at 1px in default state; `Amber` at 1px in focus state.
- **Section dividers:** Prefer spacing (24–48px) or background shifts. Use a 1px `Ash` divider only when layout alone doesn't create a clear enough boundary.
- **Sidebar boundaries:** No border - the tonal shift from Warm Gray to White creates the boundary.
- **Data tables:** 1px `Ash` borders between rows are acceptable and often necessary for scanability.
- **Never:** Thick borders (2px+), colored borders for decoration, or borders as a primary design motif.

## 3. Typography

### Philosophy

Two font families. One for brand personality (headings), one for functional precision (everything else). Plus Jakarta Sans is the **brand voice** - authoritative but human. Geist is the **functional voice** - geometric precision for all interface text.

### Font Stack

| Role       | Font              | Weight         | Size    | Tracking | Line Height | Usage                                     |
| ---------- | ----------------- | -------------- | ------- | -------- | ----------- | ----------------------------------------- |
| Display    | Plus Jakarta Sans | 700 (Bold)     | 48–72px | -0.02em  | 1.1         | Hero headlines, marketing pages           |
| Heading    | Plus Jakarta Sans | 600 (SemiBold) | 24–36px | -0.015em | 1.2         | Page titles, section headings             |
| Subheading | Geist             | 500 (Medium)   | 18–20px | 0        | 1.4         | Card titles, feature labels, sub-sections |
| Body       | Geist             | 400 (Regular)  | 15–16px | 0        | 1.6         | Paragraphs, descriptions, UI text         |
| Small      | Geist             | 400 (Regular)  | 12–13px | 0        | 1.5         | Captions, helper text, metadata           |
| Mono       | Geist Mono        | 400 (Regular)  | 13–14px | 0        | 1.5         | Tokens, board IDs, timestamps, codes      |

### Typography Rules

- **Plus Jakarta Sans** is used only for `display` and `heading` roles. Never for body text or UI labels.
- **Geist** handles all body copy, labels, buttons, and interface text.
- **Geist Mono** reinforces the craftsman's-tool identity. Use for board tokens (`go.ordre.app/XYZ`), timestamps, serial numbers, metadata, and any technical value.
- **Never use pure black** (`#000000`). Always use Midnight (`#1A1D26`) for text.
- Display type (48px+) should always use negative letter-spacing (-0.02em) for a tight, editorial feel.

## 4. Logo

### The Mark

An outlined O resting on a cursor bar. The O is drawn in the monospaced register that runs through the rest of the brand (board tokens, timestamps, serial numbers), and the Amber bar reads as a text cursor sitting under it: the job is open and something is about to be written to it.

The mark is the quietest asset in the system on purpose. It carries no meaning on its own and is not asked to. Paired with the wordmark it is unmistakable, and at 16px in a browser tab it still resolves to a ring and a rule.

### Geometry

The artwork is defined in a square 64-unit box and every other asset is derived from it by scaling. There are exactly two shapes:

| Shape      | Definition                             | Ink       |
| ---------- | -------------------------------------- | --------- |
| The O      | `rect x16 y7 32×40 rx12`, stroked at 6 | `primary` |
| Cursor bar | `rect x15 y54 34×6 rx3`, filled        | `accent`  |

Because the stroke is centred on its path, the ink spans **x 13-51** (38 wide) and **y 4-60** (56 tall). That is centred on both axes of the 64-unit box, so the mark drops into a square slot without a wrapper, and the box supplies 13 units of side padding and 4 units top and bottom for free.

**Never re-draw these numbers.** Scale the box.

### The Lockup

The mark with the wordmark set beside it, at an aspect ratio of **3.69:1**.

The wordmark sits in the same 64-unit space as the mark: Plus Jakarta Sans Bold at 49 units, tracking -0.03em, text origin at x85, baseline at y50.25. The viewBox is `13 4 206.9 56`, cut to where the "e" actually ends.

Those four numbers are measured against the shipped font file, not estimated, and they are written as literals rather than typography tokens. The viewBox hugs the word, so a type-scale token that moved would push the word past the right edge and the SVG would clip it. **If the brand font ever changes, the lockup has to be re-measured.**

### Color Variants

Four themes. Pick by the background the logo sits on, never by taste.

| Theme   | The O          | Cursor bar     | Use on                                                            |
| ------- | -------------- | -------------- | ----------------------------------------------------------------- |
| `white` | Midnight       | Amber          | Snow, Warm Gray, White - the default                              |
| `dark`  | Snow           | Amber          | Midnight sections, dark headers                                   |
| `amber` | White          | White          | An Amber fill, where Amber-on-Amber would vanish                  |
| `mono`  | `currentColor` | `currentColor` | One-color reproduction: print, engraving, embroidery, a watermark |

`mono` inherits the CSS `color` of its container rather than naming an ink, so the caller decides whether the single color is Midnight, Snow, or something else. That is what makes it safe on a dark background, where a hardcoded Midnight would disappear.

### Clear Space and Minimum Size

Keep clear space on all four sides equal to **twice the stroke weight** - 12 units at the 64-unit scale, or 19% of the mark's height. Measure it from the ink, not from the box.

The bare mark holds down to **16px**. Below that the stroke falls under 1.5px, the counter fills in, and the mark reads as a filled blob rather than a ring. The lockup holds down to **24px tall**, where the wordmark's cap height is 15px.

### Logo Don'ts

- **Don't** re-type the rect coordinates anywhere. Import the component or scale the 64-unit box.
- **Don't** recolor the mark outside the four themes. Amber-on-Amber and Midnight-on-Midnight are the failure cases the themes exist to prevent.
- **Don't** stretch the lockup. Set one dimension and let the 3.69:1 ratio drive the other.
- **Don't** rebuild the lockup by placing the mark next to live text. The gap and baseline are fixed geometry, and a flex row will not reproduce them.
- **Don't** put the bare mark on an Amber fill without switching to the `amber` theme - the Amber cursor bar disappears.
- **Don't** add a container, ring, or drop shadow to the mark. The chip is the only framed treatment.

## 5. Elevation & Depth

### Tonal Layering (Primary Method)

Depth is primarily achieved by stacking surface tiers. To make a component feel elevated, place a White (`#FFFFFF`) card on a Snow (`#FAFAF8`) or Warm Gray (`#F0EEEB`) background. The tonal contrast does the work.

### Shadows (Reserved for Interaction)

Shadows are not decorative. They are reserved for interactive feedback:

- **Hover on cards/clickable surfaces:** `box-shadow: 0 4px 16px rgba(26, 29, 38, 0.06);`
- **Modals and overlays:** `box-shadow: 0 12px 40px rgba(26, 29, 38, 0.08);`
- **Popovers and dropdowns:** `box-shadow: 0 4px 12px rgba(26, 29, 38, 0.08);`
- **Default resting state:** No shadow.

### Overlays

For floating menus, modals, and command palettes: `#FFFFFF` at 92% opacity with `backdrop-filter: blur(12px)`.

| ----- | ----- | -------------------------------------------------- |
| `xs`  | 4px   | Inline icon gaps, tight label padding              |
| `sm`  | 8px   | Between related elements, chip padding             |
| `md`  | 12px  | Input internal padding, list item vertical spacing |
| `lg`  | 16px  | Card internal padding (minimum), grid gaps         |
| `xl`  | 24px  | Card internal padding (standard), section gaps     |
| `2xl` | 32px  | Between content groups                             |
| `3xl` | 48px  | Between major page sections                        |
| `4xl` | 64px  | Hero spacing, page-level breathing room            |
| `5xl` | 80px  | Between top-level sections on marketing pages      |

### Border Radius

| Token  | Value  | Usage                                          |
| ------ | ------ | ---------------------------------------------- |
| `sm`   | 4px    | Chips, small badges                            |
| `md`   | 8px    | Buttons, inputs, small cards                   |

| `full` | 9999px | Avatars, status indicators, pill-shaped badges |

**Never use 0px radius.** Every interactive or container element should have at least `sm` (4px).

## 7. Components

### Buttons

| Variant     | Background  | Text Color | Border        | Radius | Padding   |
| ----------- | ----------- | ---------- | ------------- | ------ | --------- |
| Primary     | `#E0913E`   | `#FFFFFF`  | None          | 8px    | 12px 24px |
| Secondary   | transparent | `#1A1D26`  | 1px `#D9D6D0` | 8px    | 12px 24px |
| Ghost       | transparent | `#E0913E`  | None          | 8px    | 12px 24px |
| Destructive | `#C44B3F`   | `#FFFFFF`  | None          | 8px    | 12px 24px |

- **All buttons:** Geist Medium, 15px, letter-spacing -0.01em.
- **Hover states:** Primary → `#C67A2E`. Secondary → background `#F0EEEB`. Ghost → background `#F0EEEB`. Destructive → darken 8%.
- **Transition:** `all 150ms ease`.
- **Sizes:** Small (8px 16px, 13px text), Medium (default), Large (16px 32px, 16px text).
- **Disabled:** 40% opacity, `cursor: not-allowed`.
- **Why Primary is Amber, not Midnight:** The primary CTA must be the most visually distinct element on any screen. Midnight blends with body text and headings. Amber is the single accent color - it demands attention.

### Cards

- **Background:** `#FFFFFF` (elevated) on `#FAFAF8` or `#F0EEEB` backgrounds.
- **Border:** 1px `#D9D6D0` when on a white background. No border when tonal contrast is sufficient.
- **Radius:** 12px.
- **Internal padding:** Minimum 24px.
- **Hover (if clickable):** Apply hover shadow, no background change.

## 8. Dashboard Shell

The dashboard is the container that the provider lives inside every day. It optimizes for speed, clarity, and confidence.

### Layout Structure

- **Sidebar** (260px, fixed): Warm Gray (`#F0EEEB`) background. Full viewport height. No right border - tonal contrast creates the boundary.
- **Top bar** (64px, sticky): White (`#FFFFFF`) background at 95% opacity with `backdrop-filter: blur(12px)`. 1px Ash bottom border. Contains search bar (left) and notification bell (right).
- **Content area:** White (`#FFFFFF`) background, fills remaining space, scrolls independently. Padding: 32px.

### Sidebar Anatomy

- **Header:** "Ordre" wordmark (Plus Jakarta Sans Bold, 18px, Midnight) + provider name (Geist Medium 12px, Stone).
- **Primary CTA:** "New board" button - full-width, Amber bg, white text, 40px height, 13px Geist Medium.
- **Primary nav:** Home, Boards, Messages, Clients - Stone text, 13px, 20px Material icons. Active state: White bg + Amber text, rounded-lg.
- **Divider:** 1px Ash/30, 12px vertical margin.
- **Secondary nav:** Team, Settings - same styling, always default state.
- **Profile (footer):** Avatar initials circle (32px, Warm Gray bg, Ash border) + name + email + more icon.

### Navigation States

- **Default:** Stone text, transparent bg.
- **Hover:** Snow (`#FAFAF8`) bg, Stone text.
- **Active:** White (`#FFFFFF`) bg, Amber text. Font-weight medium (not bold). Outline icons only - no filled variants.

## 9. Tailwind Configuration

Ordre uses **Tailwind v4** with CSS-based theme configuration - there is no `tailwind.config.ts`. Design tokens live in `packages/ui/src/styles/tailwind.css` and are consumed across all apps via `@ordre/ui/styles/main`:

```css
/* packages/ui/src/styles/tailwind.css */
@theme static {
  /* === Colors === */
  --color-*: initial;
  --color-midnight: #1a1d26;
  --color-slate: #3a3f4b;
  --color-amber: #e0913e;
  --color-deep-amber: #c67a2e;
  --color-sage: #5b9a6f;
  --color-snow: #fafaf8;
  --color-warm-gray: #f0eeeb;
  --color-ash: #d9d6d0;
  --color-stone: #8a8680;
  --color-brick: #c44b3f;
  --color-white: #ffffff;

  --color-accent: var(--color-amber);
  --color-accent-strong: var(--color-deep-amber);

  /* === Fonts === */
  --font-headline: 'Plus Jakarta Sans', ui-sans-serif, system-ui, sans-serif;
  --font-body: 'Geist', ui-sans-serif, system-ui, sans-serif;
  --font-mono: 'Geist Mono', ui-monospace, SFMono-Regular, monospace;
}
```

**No Material Design tokens.** No `surface-container`, `inverse-surface`, `primary-container`, or any other Material naming. The 11 simple color names above are the entire palette.

> Spacing and border-radius tokens from section 6 are applied via Tailwind's default scale plus utility classes - they're not declared as custom theme properties yet. The fixed values in this document are the reference for how each token should be used, not a list of custom Tailwind properties.

## 10. Do's and Don'ts

### Do

- **Do** use tonal contrast as the primary depth mechanism - it's what makes the design feel physical rather than flat.
- **Do** lean into Geist Mono for small details (timestamps, board IDs, metadata). It reinforces the precision identity.
- **Do** use generous whitespace. If a screen feels busy, remove an element - don't add a container around it.
- **Do** use asymmetrical layouts on marketing pages for a custom, non-template feel.
- **Do** keep the Amber accent rare. It should feel like a deliberate highlight, not a theme color.
- **Do** use the alternating Snow/Warm Gray section pattern for visual rhythm on long pages.

### Don't

- **Don't** use gradients. Depth comes from solid tonal shifts.
- **Don't** use pure black (`#000000`). Always use Midnight (`#1A1D26`).
- **Don't** use blue. Ordre's trust signal comes from precision and warmth, not the default SaaS blue.
- **Don't** use shadows on resting elements. Shadows are earned through interaction.
- **Don't** add decorative borders, colored outlines, or thick dividers.
- **Don't** use more than two font families. Plus Jakarta Sans for headings, Geist for everything else.
- **Don't** use filled Material icons. Always use outline variants for consistency.
- **Don't** use star ratings, avatar photos, or social media icons in testimonials - keep them editorial.

## 11. Voice & Tone

### Dashboard Copy

- Labels use Geist Mono uppercase for a structured, tool-like feel.
- Descriptions are concise and scannable - no marketing language inside the app.
- Timestamps are always in Geist Mono.
