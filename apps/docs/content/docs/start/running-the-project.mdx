Ordre is a [Turborepo](https://turborepo.com/) + [pnpm workspaces](https://pnpm.io/workspaces) monorepo. From the repo root, Turborepo fans commands out to the right apps and packages.

## Prerequisites

- **Node.js** `>=24` (see [`.nvmrc`](https://github.com/ianwelerson/ordre/blob/main/.nvmrc) for the exact version)
- **pnpm** `11.x` (see `packageManager` in the root `package.json`)
- **PostgreSQL** - a local instance for the API (see [Database Roles & RLS](/internal-docs/start/database-roles))

## First-time setup

```bash
# 1. Clone and install
git clone https://github.com/ianwelerson/ordre.git
cd ordre
pnpm install

# 2. Configure environment variables (see the Environment Variables page)
cp .env.example .env
cp apps/api/.env.example apps/api/.env

# 3. Set up the database role the API connects as (one-time, manual)
#    See Setup -> Database Roles & RLS

# 4. Start the whole stack
pnpm dev
```

The three setup steps each have their own page: **[Environment Variables](/internal-docs/start/environment-variables)** and **[Database Roles & RLS](/internal-docs/start/database-roles)**.

## Local hostnames - portless

Every app runs behind a stable HTTPS hostname locally via [portless](https://www.npmjs.com/package/portless) instead of juggling `localhost` ports. Cookies, CORS, and OAuth-style flows then behave the way they do in production, and cross-app links resolve the same locally as once deployed.

Each app keeps its own raw dev server (`*:dev:app`); portless is a thin HTTPS proxy in front, wired through Turborepo. Each app declares a `portless` block in its `package.json` (a `name` and the underlying dev `script`); the root `portless.json` enables the Turborepo integration.

## Dev URLs

`pnpm dev` (from the root) starts the frontend apps together. The API, docs, and Storybook have their own root scripts:

| App            | Command          | Dev URL                             |
| -------------- | ---------------- | ----------------------------------- |
| Marketing      | `pnpm dev`       | `https://ordre.localhost`           |
| Dashboard      | `pnpm dev`       | `https://dashboard.ordre.localhost` |
| Board          | `pnpm dev`       | `https://board.ordre.localhost`     |
| API            | `pnpm api:dev`   | `https://api.ordre.localhost`       |
| Docs           | `pnpm docs:dev`  | `https://docs.ordre.localhost`      |
| Storybook      | `pnpm storybook` | `https://storybook.ordre.localhost` |
| Email previews | `pnpm email:dev` | `https://email.ordre.localhost`     |

## Running one app at a time

Run a single app from the root with a filter, or from its own directory:

```bash
pnpm --filter dashboard dev      # from the root
# or
cd apps/dashboard && pnpm dev
```

To bypass the HTTPS proxy and run a raw dev server on its default port, use the matching `*:dev:app` script:

| App            | Raw dev script           | Default port                   |
| -------------- | ------------------------ | ------------------------------ |
| Marketing      | `pnpm dev:app`           | `http://localhost:3000`        |
| Dashboard      | `pnpm dev:app`           | `http://localhost:3000`        |
| Board          | `pnpm dev:app`           | `http://localhost:5173`        |
| API            | `pnpm api:dev:app`       | `http://localhost:3000`        |
| Docs           | `pnpm docs:dev:app`      | (OpenAPI watcher + `next dev`) |
| Storybook      | `pnpm storybook:app`     | `http://localhost:6006`        |
| Email previews | `pnpm email:dev:preview` | `http://localhost:3000`        |

## Common root scripts

| Command            | Description                                   |
| ------------------ | --------------------------------------------- |
| `pnpm dev`         | Start every frontend app in watch mode        |
| `pnpm build`       | Build every app and package for production    |
| `pnpm lint`        | Run ESLint across the monorepo                |
| `pnpm check-types` | Run TypeScript type-checking                  |
| `pnpm format`      | Format everything with Prettier               |
| `pnpm test:unit`   | Run unit tests with coverage                  |
| `pnpm db:migrate`  | Apply pending database migrations             |
| `pnpm email:build` | Compile `@ordre/email` for the API to import  |
| `pnpm email:dev`   | Preview every email template, in both locales |

Each app README lists its own app-specific scripts.

## Email templates

`pnpm email:dev` runs the React Email preview server over
[`packages/email/emails/`](https://github.com/ianwelerson/ordre/blob/main/packages/email),
which holds one entry per template **per locale** - `invite-created.en` beside
`invite-created.pt` - so the Portuguese gets looked at rather than assumed.

`pnpm email:build` is the only build step in the repo. `pnpm api:dev` and
`pnpm check-types` both depend on it through Turbo, so it normally runs on its own;
you only need it by hand after a template change if you are starting the API some
other way. [The API Runtime](/internal-docs/architecture/runtime) explains why this
one package is compiled when nothing else is.
