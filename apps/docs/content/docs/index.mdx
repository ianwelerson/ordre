Ordre is a client communication platform for service providers. It gives every
job a private, shareable status board that clients can follow in real time - no
app download, no account creation, just a link.

This is the internal documentation: how the product works, how the codebase is
organized, the infrastructure behind it, and how it is priced. The
[API Reference](/api-docs) is generated from the live OpenAPI spec.

## About this project

<Callout title="On the project">
  Ordre is a **study project**. It exists to explore product concepts, libraries, patterns, and
  monorepo architecture in depth. Some parts are **intentionally overengineered** (layered packages,
  swappable service interfaces, multi-app setup, and so on) because the goal is to learn by
  building, not to ship the smallest possible MVP.
</Callout>

<Callout title="On AI usage">
  AI is part of the development process, but deliberately kept away from the core of it. It's used
  for supporting tasks - drafting and refining documentation, writing code comments, and as a search
  resource alongside the official docs and the wider internet. The goal is to lean on AI **as little
  as possible for the actual coding**, because the whole point is to learn, practice, and explore by
  writing the code myself. That said, this is transparency, not a claim that AI plays no part in the
  work.
</Callout>

<Callout title="Built like a real product">
  Even though it's a study project, Ordre is designed and documented **as if it were a real product
  heading to market**. That's why the docs go all the way down to pricing tiers, a founding-member
  strategy, payout constraints, and a launch roadmap - working through those decisions is part of
  the exercise, not set dressing.
</Callout>

The [API Reference](/api-docs) documents every endpoint of the Ordre REST API,
with an interactive playground for trying requests. It is generated from the
OpenAPI spec that `apps/api` produces, so it always matches the deployed
contract.

## The product in one minute

A workspace member creates a **board** for each job, picks a template for their
industry, and shares a unique link. The client opens it - no login - and sees a
live timeline of updates, photos, approvals, and chat. Sensitive fields stay
blurred until the client verifies their identity. Everything about the job lives
in one place.
