## Billing

### `plan`

✅ **Built** - `packages/db/src/schemas/billing.ts`

The plan catalog - the subscribable tiers and their limits. Global, not
workspace-scoped. Seeded from [`packages/db/src/seeds/plan.ts`](https://github.com/ianwelerson/ordre/blob/main/packages/db/src/seeds/plan.ts);
there is no admin API for plans.

| Field          | Type                              | Notes                                                                        |
| -------------- | --------------------------------- | ---------------------------------------------------------------------------- |
| `id`           | uuid                              |                                                                              |
| `code`         | enum, unique                      | `<tier>:<variant>`, e.g. `free:founding`                                     |
| `tier`         | enum `free \| paid`               | Derived from `code`, stored so it can back the index                         |
| `status`       | enum `active \| legacy \| closed` |                                                                              |
| `title`        | text                              | Display name                                                                 |
| `description`  | text                              |                                                                              |
| `entitlements` | jsonb                             | `{ limits: { seat?, location? } }` - defaults to `{ limits: {} }`, see below |
| `createdAt`    | timestamp                         |                                                                              |
| `updatedAt`    | timestamp                         |                                                                              |

Unique: (`code`); partial unique on (`tier`) where `status = 'active'`, as
`plan_one_active_per_tier`, so "the current free/paid plan" is a single
well-defined row while legacy plans of the same tier coexist. `tier` is derivable
from `code` but stored anyway, because an index expression over `code::text` is
not allowed - the enum cast is not `IMMUTABLE`.

**Limits live in `entitlements`, not in columns.** A new limit is a new key in the
`PLAN_LIMITS` enum with no migration. Within `limits`, a number caps the resource,
and `null` - or the key being absent - means unlimited:

```jsonc
{ "limits": { "seat": 2, "location": 1 } } // free:founding
{ "limits": { "seat": 20, "location": 3 } } // paid:founding
```

A **seat** is held by an active member _or_ a pending invite, the workspace owner
included - so it counts people the workspace has committed to, not members it
currently has. `requireWorkspaceQuota` enforces both limits at the routes that
consume one (see [Authorization](/internal-docs/architecture/authorization)).

Because the blob is JSONB, Postgres will accept a typo'd key that the type system
never sees, and an unrecognised key would read as "unlimited". The guard therefore
re-validates `entitlements` against its Zod schema on every check and refuses the
request (`500 PLAN_ENTITLEMENTS_INVALID`) rather than treating a malformed plan as
uncapped.

### `workspace_subscription`

✅ **Built** - `packages/db/src/schemas/billing.ts`

One per workspace (Settings → Plan & usage, Team seats). Limits come from the
linked `plan`. A workspace is subscribed to the active free plan at creation.

| Field                | Type                       | Notes                                                 |
| -------------------- | -------------------------- | ----------------------------------------------------- |
| `id`                 | uuid                       |                                                       |
| `workspaceId`        | fk → workspace             | `on delete cascade`                                   |
| `planId`             | fk → plan                  | `on delete restrict` - a plan in use can't be deleted |
| `status`             | enum `active \| cancelled` | Defaults to `active`                                  |
| `currentPeriodStart` | timestamp, nullable        |                                                       |
| `currentPeriodEnd`   | timestamp, nullable        |                                                       |
| `cancelAtPeriodEnd`  | boolean                    |                                                       |
| `createdAt`          | timestamp                  |                                                       |
| `updatedAt`          | timestamp                  |                                                       |

Partial unique on (`workspaceId`) where `status = 'active'`, as
`workspace_subscription_one_active_per_workspace` - a workspace has at
most one active subscription, while cancelled rows accumulate as history. Reads
therefore filter to the active row rather than assuming a single row per workspace.

`[derived]`: seats used, active boards, messages this month.

<Callout type="info">
  Stripe columns (`stripeCustomerId`, `stripeSubscriptionId`) and the `trial` / `past_due` statuses
  are **not implemented yet** - they arrive with the payment integration. Today a subscription is
  created directly, only ever `active` or `cancelled`.
</Callout>
