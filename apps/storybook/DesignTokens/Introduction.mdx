# Design Tokens

Design tokens are the shared vocabulary of the **@ordre/ui** design system - the named values (colors, fonts, icons, …) every surface reads from instead of hard-coding hex values, pixel sizes, or bespoke SVGs.

They live as Tailwind v4 CSS variables in `packages/ui/src/styles/tokens/`, one file per group, all pulled together by `styles/tailwind.css`. That means every token is available **three** ways:

- a CSS custom property - `var(--color-amber)`
- a generated Tailwind utility - `bg-amber`, `text-amber`, `border-amber`, …
- an `@ordre/ui` export - e.g. `<Icon name="ordre-logo" />` for iconography

## Why tokens

- **Consistency** - one source of truth means the same "amber" appears on every button, border, and hover state.
- **Theming** - semantic aliases (e.g. `--color-accent → --color-amber`) let the palette shift without touching call sites.
- **Low drift** - hex values and ad-hoc SVGs don't creep into feature code.

## What's in the system

Each page below documents one file in `styles/tokens/`, and ends with how to add a step to that scale.

- **[Colors](?path=/docs/design-tokens-colors--docs)** - the raw palette plus the semantic tokens built on it.
- **[Type Scale](?path=/docs/design-tokens-type-scale--docs)** - the `--font-headline`, `--font-body`, and `--font-mono` families (Plus Jakarta Sans, Geist, Geist Mono), sizes, weights, tracking, and line heights.
- **[Spacing](?path=/docs/design-tokens-spacing--docs)** - the 4px scale behind `p-*`, `gap-*`, `w-*`, and everything else spacing-aware.
- **[Radius](?path=/docs/design-tokens-radius--docs)** - corner rounding, from chips to modals.
- **[Shadows](?path=/docs/design-tokens-shadows--docs)** - elevation and focus rings, named for intent rather than depth.
- **[Motion](?path=/docs/design-tokens-motion--docs)** - durations and easing curves.
- **[Breakpoints](?path=/docs/design-tokens-breakpoints--docs)** - the responsive stops.
- **[Containers](?path=/docs/design-tokens-containers--docs)** - the max-widths pages are laid out against.
- **[Iconography](?path=/docs/design-tokens-iconography--docs)** - custom SVGs plus the full Lucide set, exposed through a single `<Icon />` component.

## Using tokens

```tsx
// Tailwind utilities (preferred for layout and components)
<h1 className="font-headline text-foreground">Hello</h1>
<button className="bg-accent hover:bg-accent-strong text-white">Save</button>

// Raw CSS variable (when inline styles or CSS-in-JS are unavoidable)
<div style={{ background: 'var(--color-background)' }} />

// Shared components that already consume tokens
import Icon from '@ordre/ui/icons';
<Icon name="ordre-logo" />
```

Reach for a semantic token - `background`, `foreground`, `border`, `button`, `success`, `invalid`, `info` - whenever the value carries meaning, and a raw palette name (`amber`, `sage`, `brick`, `midnight`) only when you truly need that specific hue. The semantic layer is what lets the palette move without a find-and-replace.

## Adding or changing a token

1. Edit the matching file in `packages/ui/src/styles/tokens/`, under its `@theme static` block. A new group needs an `@import` in `styles/tailwind.css` too.
2. Add it to the scale table on that group's page in this section, so it is discoverable rather than just present.
3. Prefer adding a semantic alias over renaming a raw token: aliases protect consumers from breaking changes when the underlying value shifts.
